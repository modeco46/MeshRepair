# Большие модели: диагностика и исправления 1.0

## Что установлено по журналу

- Модель 518 194 грани имеет 11 884 пересекающиеся грани. После воксельного ремонта и удаления 50 мелких оболочек остаются 3 066 764 грани и девять оболочек. Все шесть попыток упрощения отклонены с `kept_shell_count_changed`; итоговый ремонт сохраняется без упрощения. Это откат кандидатов, а не отсутствие запуска децимации.
- Для модели 894 562 грани журнал обрывается после начала `Восстановление поверхности`, шаг 0,02 мм. На скриншоте идёт 374-я секунда этого этапа. Упрощение ещё не запущено. Одних логов недостаточно, чтобы различить долгий расчёт и зависание GPU-драйвера на этой конкретной модели.
- В том же журнале другая сетка успешно упрощена с 806 704 до 1 280 граней. Жёсткого порога отказа 500 000 граней нет.

## Подтверждённые дефекты

### Исчезновение оболочки

`decimateMesh` разрешает удалить замкнутый тетраэдр целиком, если ошибка достаточно мала. Защита только компонентов с числом граней <50 пропускала физически маленькие тела, содержащие сотни граней. Такой компонент мог исчезнуть уже в первом проходе, а более крупный — после нескольких проходов. Внешняя проверка числа оболочек правильно отклоняла весь кандидат.

Воспроизведение: сфера из 64 800 граней плюс отдельная сфера радиусом 0,001 мм из 800 граней. Версия 0.9.1 оставляла одну оболочку вместо двух. Исправление обрабатывает связные компоненты отдельно и ограничивает число удалений: минимум четыре грани на компонент в каждом проходе. Компоненты <50 граней сохраняются без изменения. Общие проверки остаются после сборки кандидата.

### Ограничения параллельного прохода

В закреплённом [исходнике MeshLib](https://github.com/MeshInspector/MeshLib/blob/v3.1.4.297/source/MRMesh/MRMeshDecimate.cpp) `decimateMeshParallelInplace` подставляет собственные `parts[i].bdVerts`, игнорируя переданные углы и границы. Воспроизведение на открытой плоскости из 64 800 граней: версия 0.9.1 сокращала граничные вершины с 720 до 12 при трёх участках; последовательный проход сохраняет все 720.

Проходы с ограничениями теперь последовательные. Остальные замкнутые оболочки остаются параллельными, без Python callback из нативных потоков. `decimateBetweenParts=True` задан явно. Разбиение ограничено восемью частями: подготовка частей в SDK многократно обходит сетку.

Гипотеза о том, что любое разбиение блокирует схлопывание плоскостей, не подтверждена. Старый код схлопывает куб из 786 432 граней до 12 при трёх участках, но оставляет 96 при шестнадцати. Последовательный вариант оставляет 26; все восемь углов и исходная поверхность сохранены. Минимальная возможная триангуляция не гарантируется.

### Плотный воксельный объём

В [MRVDBConversions.cpp](https://github.com/MeshInspector/MeshLib/blob/v3.1.4.297/source/MRVoxels/MRVDBConversions.cpp), `makeSignedByWindingNumber` вызывает `denseFill(activeBox)` и `topologyUnion`. Поэтому обычный `offsetMesh(HoleWindingRule)` уплотняет bbox даже для кольца с большой пустой серединой. Оценка площади/шаг² описывала поверхность, но не память и работу этого этапа, зависящие от объёма/шаг³.

При оценке >64 млн ячеек используется `mcOffsetMesh` с тем же шагом. CPU вычисляет `FunctionVolume` по слоям; CUDA `IFastWindingNumberByParts` передаёт блоки в нативный mesher. Внешний winding без интерфейса по частям не передаётся большому пути, поскольку он отключает `memoryEfficient`. Sharpening использует свой нативный маршрут с аналогичной защитой. Другой mesher меняет триангуляцию: после него обязательны прежние проверки, и точность ремонта относительно повреждённого исходника по-прежнему не сертифицируется.

## Проверки

`python -m pytest -q tests/test_large_meshes.py`

На Linux, Python 3.12, MeshLib 3.1.4.297, три доступных CPU, без GPU:

| Модель | Результат |
|---|---|
| Куб, 786 432 грани, 16 запрошенных участков | 26 граней; углы сохранены; замкнут; пересечений нет; двустороннее измеренное отклонение <10⁻⁶ мм |
| Тор, 800 000 граней | 6 340 граней; отклонение 0,01756 мм; полный `engine.run` около 21 с |
| Тор + 8 плотных маленьких сфер, 806 400 граней | 6 416 граней; девять оболочек после STL round-trip; отклонение 0,01891 мм; полный прогон около 21 с |
| Открытая плоскость, 64 800 граней | Все 720 граничных вершин сохранены в обоих режимах упрощения |
| Перекрывающиеся кубы, принудительный маршрут по слоям | Нативное восстановление завершено; одна замкнутая оболочка без пересечений; шаг неизменен |
| Перекрывающиеся кубы, bbox 414³ = 70 957 944 ячейки, шаг 0,02 мм | Обычный путь: пиковый RSS 1 289 МиБ, 5 675 428 граней. По слоям: 496 МиБ, 2 014 796 граней. Обе сетки прошли проверку; шаг не менялся |

Последний замер воспроизводится `python tests/benchmark_large_volume.py --backend dense` и `--backend auto` (отдельные процессы; Linux сообщает пиковый RSS). Он проверяет реальное превышение порога, а не только подмену порога в тесте. Длительность не используется для сравнения: во время одного из прогонов выполнялись другие тесты.

Числа и время относятся к единичным синтетическим прогонам, не являются гарантией для произвольной модели. Процессные тайм-ауты в регрессиях защищают CI от зависания. Пользовательские модели отсутствуют среди приложений; точное сравнение на них и физической RTX 3090 не выполнено. CUDA покрывается проверками интерфейсов/fallback, а геометрия нового маршрута проверяется настоящим CPU SDK.
