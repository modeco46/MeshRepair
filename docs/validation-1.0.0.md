# Проверка выпуска 1.0.0

Основой служат присланные `meshrepair-1.0.0.patch` и ZIP с 14 полными файлами, база `49bbc1e`.
Патч применён без изменения, результат побайтно сверен с ZIP. Затем исправлены обнаруженные
при проверке крайние случаи и сохранены дополнительные регрессии.

## Подтверждённые причины

- Воксельный результат содержал отрицательные внутренние оболочки и пластины практически нулевого объёма.
  Они удаляются по объёму, а не увеличением порога 50 граней.
- Поздний неудачный QEM-проход мог отменять ранний допустимый результат. Для единственной оставшейся
  оболочки проверяется каждый проход, а поиск может опускаться ниже прежнего масштаба 0,15.
  Для нескольких оболочек сохранён переход к `propose_reduction_by_shell` после первого отказа
  по топологии/числу оболочек с повтором того же масштаба ошибки.
- Чистые пересечения между замкнутыми оболочками допускают булево объединение без вокселей.
  Ограничение времени проверяется также после возврата нативной операции, чтобы поздний результат
  не принимался при отсутствии промежуточного callback.
- Внутренние вершины удалённых поверхностей учитывались как отклонение формы. Они теперь классифицируются
  через `Mesh.signedDistance` и остаются видимыми в отдельных полях отчёта и карте отклонений.
- Площадь не определяет объём работы вокселизации. Сохраняются оценка по сетке bbox, проба с шагом ×4,
  предупреждение о времени и ранний отказ при превышении 6 млрд ячеек.

Гипотеза, что разбиение `subdivideParts` объясняет все отказы крупных моделей, не подтверждена.
Общий режим сохраняет параллельное разбиение. Только плоский проход выполняется без разбиения,
как в предоставленном патче.

## Дополнительные проверки восстановления

Для объёмов свыше 64 млн ячеек используется Marching Cubes по слоям/частям с прежним шагом.
CPU применяет `FunctionVolume`; CUDA — интерфейс `IFastWindingNumberByParts`. Неподходящий внешний
winding не отключает экономный CPU-путь. Для замкнутого CPU-входа расчёт может пропускать области
далеко от поверхности; если результат открыт, выполняется повтор с полным полем.

Небольшое число пересечений обычной воксельной поверхности получает локальную попытку ремонта.
Принимается только результат с прежним числом оболочек, без дыр/пересечений и с проверенной границей
смещения всей поверхности не более четверти шага. Неудачный ремонт откатывается. Полный результат
Sharpening этим способом не меняется. `touchIsIntersection=False` отключает глобальную предварительную
обработку вырожденных граней SDK, которая удаляла посторонние маленькие оболочки.

## Границы проверки

Физическая CUDA в проверочной среде недоступна. Зависание конкретного драйвера/GPU не воспроизведено;
уменьшение памяти CPU-пути не устанавливает причину такого зависания. Для его исследования нужны
строки журнала с размерами сетки, оценкой по пробе, `compute_device` и сравнение с режимом «Без CUDA».

## Команды проверки

```sh
QT_QPA_PLATFORM=offscreen python -m pytest -q
python tests/benchmark_synthetic.py
python tests/benchmark_090.py --real tests/data/test.stl --one-cpu --json b.json
xvfb-run -a python tests/check_viewport.py
```

Windows CI отдельно собирает EXE и запускает `tests/check_bundle.py`; этот скрипт не импортирует
исходный пакет `meshrepair`. Публикация использует успешную Windows-сборку точного коммита `main`.
