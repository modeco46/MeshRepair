# План развития

## 0.1 — экспериментальная вертикальная цепочка

Реализованы: запуск без компиляторов, русский Tk-интерфейс, отдельный процесс, отмена, CPU/CUDA выбор, диагностика, полное перестроение, проверка замкнутости/топологии/пересечений/числа компонентов, двусторонняя оценка расстояний по вершинам, JSON-отчёт и Windows CI/упаковка.

Целевой допуск: 0,001–0,02 мм. Никакой сертификации точности. Реальные 10 млн треугольников, пользовательская RTX 3090 и драйверы пока не испытаны. Нативный SDK используется через Python; переписывание интерфейса на C# не требуется для ускорения этих операций.

## 0.2 — измерения на реальных моделях и бережный ремонт

1. Собрать набор пользовательских моделей: дырки, смешанные нормали, самопересечения, тонкие кромки, посадочные места, 1/5/10 млн треугольников. Не публиковать модели автоматически.
2. Измерять wall time этапов, peak RAM/VRAM, число исходных/выходных граней. Сравнить CPU и CUDA при одинаковых параметрах.
3. Добавить локальные операции ремонта; исправные участки сохранять неизменными.
4. Отдельно учитывать пропущенные при загрузке грани, повторяющиеся треугольники и потерянные области.
5. Добавить управление потоками через проверенный API нативного ядра, не неподтверждённые переменные окружения.

## 0.3 — геометрическая точность

1. Разделить сохранённые участки, новые заплатки и удалённые внутренние оболочки.
2. Проверять непрерывные расстояния по поверхностям с контролируемой верхней границей ошибки; выборку явно маркировать как оценку.
3. Общий бюджет погрешности ремонта, сшивки, упрощения и экспорта; проверка после повторного чтения экспортированного файла.
4. Защищённые области, острые кромки, минимальные толщины, цветовая карта отклонений.
5. Не выдавать «допуск соблюдён» без завершённой строгой проверки.

## 0.4 — большие модели

Локальное перестроение, разреженные объёмы или блоки с перекрытием, проверка стыков и корректное освобождение памяти. Реализовывать только после профилирования. У GPU нет универсального преимущества для всех задач топологии.

## Интерфейс и распространение

Добавить лёгкий 3D-просмотр, очередь файлов, сохранение профилей, выбор единиц и ограничений ресурсов. Автоматическая Windows-сборка сейчас через GitHub Actions; позднее стабильные Releases, проверка на Windows 10 и подпись бинарников.

## Критерий приёмки

На согласованных моделях: проверенная топология, отсутствие пересечений, согласованная политика компонентов и дыр, корректная геометрия, измеренное время/память, явно указанный уровень проверки допуска. Нельзя считать закрытую, но искажённую сетку успешным ремонтом.
