# MeshRepair 1.0.0

Исправление ювелирных сеток: **выберите файл → задайте качество → исправьте → «Сохранить…»**. Интерфейс русский; единицы всегда миллиметры. Исходник не перезаписывается.

## Крупные модели (1.0.0)

- Если замкнутые оболочки только пересекают друг друга, они объединяются булевой операцией без вокселей.
- После воксельного ремонта внутренние полости и пластины нулевой толщины удаляются (полости внутри детали не сохраняются).
- Перед воксельным расчётом журнал показывает размер сетки и оценку времени по пробе; при слишком большой сетке
  расчёт не начинается, а сообщение называет допуск, при котором он реален.
- Отклонение не считает вершины исходника внутри тела результата (внутренние поверхности); их число и максимум
  выводятся отдельной строкой отчёта.

## Скачать и запустить

Готовые Windows-сборки публикуются в [GitHub Releases](https://github.com/modeco46/MeshRepair/releases). Для версии 1.0.0 имя архива — `MeshRepair-1.0.0-windows-x64.zip`; выпуск появляется после успешной сборки и публикации соответствующего тега. Распакуйте весь ZIP и запустите `MeshRepair.exe`, сохранив папку `_internal` рядом.

Для EXE не нужны Python, Visual Studio или CUDA Toolkit. Для CUDA нужен совместимый драйвер NVIDIA, для 3D — OpenGL 3.2+. Отображение и CUDA являются разными подсистемами. Из исходников: Python 3.12 x64, `start.cmd` на Windows либо `pip install -r requirements.txt` и `python launch.py`.

## Работа с моделью

- Открытие STL, OBJ, PLY: «Выбрать файл…», Ctrl+O или перетаскивание.
- «Проверить» диагностирует отображаемую сетку без изменения файла. «Исправить сетку» всегда обрабатывает исходник.
- Качество / допуск: 0,001–0,5 мм. Принимаются точка и запятая. Меньший шаг обычно требует больше времени и памяти.
- Упрощение необязательно: отдельное схлопывание плоскостей с углом 0–45° либо общее упрощение поверхности. При общем упрощении поле угла отключено; обе галочки используют общее упрощение с единым бюджетом ошибки относительно поверхности до упрощения.
- «Строго доказывать допуск» выключено по умолчанию: применяется быстрое двустороннее измерение по вершинам. При включении требуется численная граница для всей поверхности.
- «Удалять мелкие оболочки (< 50 граней)» выключено по умолчанию. Без неё мелкие тела сохраняются и исключаются из децимации. Если все тела мелкие, удаление отменяется, чтобы не создать пустую сетку.
- «Восстанавливать острые рёбра» включает пробу Sharpening перед воксельным восстановлением. «Склеивать близкие вершины» отдельно разрешает склейку с порогом 0,1 × шаг; по умолчанию выключено.
- «Без CUDA» принудительно отключает CUDA winding и проекции, в том числе инициализацию этих модулей. По умолчанию CUDA выбирается автоматически.
- «Остановить» завершает отдельный рабочий процесс; таймера принудительного прерывания нет.

3D-окно показывает все треугольники. ЛКМ вращает, СКМ перемещает, колесо масштабирует. Есть исходник/результат, поверхность/рёбра, стандартные виды и карта отклонений. Карточка «Связные части» показывает топологические фрагменты: несогласованные нормали могут разделять одну физическую деталь на множество фрагментов при загрузке.

«Отчёт» содержит диагностику, этапы, причины отказа упрощения с кодами, оболочки и горячие точки отклонений. «Журнал» поддерживает выделение, Ctrl+C, копирование всего текста и очистку. Настройки сохраняются между запусками.

## Сохранение и временные файлы

Ремонт **по умолчанию ничего не создаёт рядом с исходником**. После успеха доступна кнопка **«Сохранить…» / Ctrl+S**. По умолчанию выбран только STL, путь — `<исходник>_repaired.stl`. Дополнительно можно выбрать:

| Пункт | Имя рядом с выбранным STL |
|---|---|
| STL | `имя.stl` |
| JSON-отчёт | `имя.stl.json` |
| Карта отклонения | `имя.stl.deviation.npz` |
| Журнал | `имя.stl.log.txt` |

Записываются только отмеченные файлы. JSON создаётся из текущего отчёта и содержит выбранный итоговый путь, UTC-время сохранения и список файлов. Для существующих выбранных файлов запрашивается подтверждение; исходник и рабочие артефакты перезаписать нельзя. Каждый файл сначала полностью записывается в `<имя>.part` в той же папке, затем заменяется через `os.replace`. При ошибке временные `.part` этого сохранения удаляются. Атомарен каждый файл отдельно: ошибка диска между несколькими заменами может оставить неполный набор; GUI сообщает ошибку и сохраняет рабочий результат.

После сохранения показываются пути и размеры. Результат остаётся доступным во временной папке: можно повторно сохранить его в другое место или выбрать другие дополнения. Сохранение только JSON/журнала не считается сохранением геометрии. Закрытие, открытие другого исходника и повторный ремонт с несохранённым результатом требуют выбора «Сохранить… / Не сохранять / Отмена».

Флажок «Сохранять автоматически рядом с исходником» выключен по умолчанию. При включении сохраняется STL под свободным именем `_repaired`, `_repaired_1` и т. д.; дополнительные файлы доступны через диалог.

Рабочие папки: `<системный temp>/meshrepair-job-<uuid>/`, с `owner.pid`. Поле «Папка временных файлов» позволяет указать другую папку, включая RAM-диск. Перед обработкой проверяется свободное место: ориентир `треугольники × 50 байт × 2`. Это оценка диска, не гарантия достаточности RAM или размера будущего воксельного ремеша.

Промежуточные сетки хранятся как `mm.Mesh` в RAM. Worker пишет итоговые `result.stl` и `deviation.npz`, а также небольшой канал результата GUI. `view.npz` находится в отдельном таком же задании и удаляется после чтения. Папки принадлежат экземпляру приложения: удаляются при остановке, смене файла, закрытии и через `atexit`. После аварии следующий запуск чистит задания старше 24 часов только с заведомо мёртвым PID; неизвестный/живой владелец сохраняется. Старые `.meshrepair-*` возле открытого исходника однократно проверяются на возраст >24 ч. Windows-проверка PID использует `ctypes`, новых зависимостей нет.

## Порядок ремонта и проверки

1. Загрузка с проверкой NaN/inf, согласование ориентации и **одна полная диагностика исходника**. Точная склейка и граф ориентации работают в NumPy/SciPy. Конфликтующая неориентируемая компонента не блокирует исправление остальных.
2. Для выбора заплаток используются дешёвые топологические счётчики. Простые дыры заполняются независимо от общего количества дыр/оболочек: плоские — триангуляцией, остальные — `fillHoleNicely`. Проверяются изменённые грани, включая сдвинутые соседние грани, и все треугольники, пересекающие bbox изменений. Это сохраняет правила MeshLib для общих вершин/рёбер и не ищет пересечения по всей модели на каждую дыру. Заплатки с `patch_self_intersections` принимаются условно до общего локального ремонта; остальные неудачные заплатки откатываются полностью.
3. После дыр выполняется **одна полная проверка**. При `0 < число пересекающихся граней ≤ max(200, 0,1% граней)` сначала пробуется `SelfIntersections.fix` с `CutAndFill`. Пороги задаются в `Settings.local_fix_max_faces` и `local_fix_fraction`. Результат принимается только при замкнутости, корректной топологии и нуле пересечений. В отчёте записываются число пересекающихся граней и `accepted_with_local_fix`. Если локальный ремонт не принят или превышен порог, условные заплатки отменяются вместе со сдвигами старых вершин; безопасные заплатки восстанавливаются из исходной стадии, затем выполняется воксельный путь. Это не воксельная функция `fixSelfIntersections(mesh, voxelSize)`.
4. Для корректной поверхности сохраняется исходная геометрия либо объединяются замкнутые тела. Ограничение 32 относится только к последовательному булеву объединению; большее число корректных тел сохраняется без вокселей.
5. Если нужен OpenVDB, сначала показывается оценка `площадь / шаг²`. Sharpening пробуется с шагом ×4; малое число дефектов замкнутой пробы можно исправить CutAndFill с повторной проверкой. Невалидная проба отключает Sharpening. Полный результат проверяется в памяти, в итоговых координатах. Если он невалиден, автоматически выполняется обычный `offsetMesh` с тем же шагом, когда оценка `площадь / шаг² × 90 с / 1 млн` не превышает 120 с (`Settings.sharpening_fallback_max_seconds`). При большей оценке GUI показывает «Повторить без Sharpening»: один клик запускает ремонт с настройками неудавшегося задания. Оценка ориентировочная, а не гарантированный таймаут. Причина, оценка и фактическое время записываются в отчёт. CutAndFill к полному результату Sharpening не применяется. Грубая проба никогда не публикуется под видом выбранного качества. При повторе сохраняется уже построенный CUDA winding; после ошибки CUDA дальнейшие проходы используют CPU. Каждый полный кандидат проверяется один раз, без дублирующей проверки перед необязательными стадиями.

6. При упрощении очистка плотной сетки заранее пропускается. Кандидат проверяется в памяти; очистка применяется к малому кандидату только при невалидности и вырожденных гранях. Без упрощения очистка запускается только при ненулевом дешёвом счётчике вырожденных граней. Изменение топологии/числа оболочек откатывает очистку.
7. Проверенная итоговая сетка записывается **один раз**, STL загружается и диагностируется. Кандидаты упрощения и очистки на диск не пишутся. При дефекте экспорта берётся предыдущая стадия из памяти, повторяется запись и контроль; откат упрощения виден в отчёте. В обычном успешном прогоне один round-trip. Загрузчик STL может разделить совпадающие воксельные швы на дополнительные оболочки: сначала откатываются необязательные стадии; если базовый STL при этом замкнут, топологически корректен и не имеет пересечений, он доступен с явным предупреждением `stl_shell_count_changed` и фактическим числом оболочек.

Ограничения одной заплатки: bbox ≤10 мм, ≤2048 граничных рёбер, оценка/размер ≤50000 граней, ≤20000 разделений рёбер. Бюджет этапа 60 с проверяется между нативными вызовами. Пропущенные/отклонённые дыры передаются объёмному восстановлению. Разреженный метод не выделяет плотную сетку на весь bbox, но очень малый шаг всё равно может потребовать много RAM.

## Допуск и отклонение

При общем упрощении выполняется до трёх последовательных QEM-проходов; проход, удаливший менее 3% граней, завершает цепочку. `maxError = допуск × error_scale` одинаков для всех проходов кандидата. Подбор `error_scale` — бинарный поиск в (0; 0,8], максимум шесть кандидатов. Цель измерения — не более 95% допуска; поиск заканчивается раньше при попадании в пределах 1% от этой цели или практически нулевой ошибке плоского схлопывания. Все кандидаты строятся заново от исправленной поверхности, все измерения относятся к ней, а не к предыдущему проходу. Из подходящих кандидатов сохраняется самый маленький: QEM не строго монотонен. В строгом режиме доказательство запускается после подбора; при отказе масштаб уменьшается на 20%, не более двух повторов. Если после поверхностного ремонта без вокселей первый проход удалил >90% граней, дальнейшие проходы закрепляют угловые вершины выраженных рёбер, чтобы почти плоский клин не смещал углы при переинициализации QEM. На плотных шероховатых поверхностях это ограничение не включается. Смысл галочек и угла не изменён; шум поверхности не сглаживается.

**По умолчанию — «измерено»:** `rd.measured_distance`, вершины → поверхность в обе стороны, без запуска строгого доказательства. **С галочкой — «доказано»:** `verify_surface_bound`, адаптивное разбиение и численные верхние границы для всей поверхности, float64 с численным запасом. Это не доказательство в точной арифметике. Неопределённость строгого режима отклоняет кандидата. Отказ всех попыток сохраняет ремонт без упрощения и показывает русскую причину/код.

Допуск упрощения относится к **исправленной поверхности до упрощения**, а не к повреждённому исходнику. Отдельно после локального ремонта и для итогового STL измеряются расстояния всех вершин исходника до результата: максимум, количество >2×шага и координаты худших точек. Карта односторонняя, поэтому не гарантирует обнаружение добавленных пузырей и внутренних дефектов. В `deviation.npz` сохранены все вершины и расстояния; синий — ноль, жёлтый — два шага, красный — больше двух шагов.

Раздельные замкнутые оболочки сохраняются без искусственных перемычек. CutAndFill может отделить мелкую оболочку; в отчёте указаны число граней, bbox и положение. Воксельный ремонт/объединение может изменить внутренние полости или потерять детали мельче шага. Общая точность ремонта не сертифицируется.

## Время и вычислительное устройство

Журнал содержит фактическое время этапов и `compute_device`, JSON — `stage_timings`, `voxel_passes` и `acceleration`. Без новых сообщений прогресса GUI каждые 5 с показывает «идёт X с, этап без процентов». Остановка остаётся доступной, в том числе при нативном вызове без Python callbacks.

| Операции | Устройство |
|---|---|
| Топология, пересечения, CutAndFill, decimation, OpenVDB | Нативный CPU; многопоточность на поддерживаемых этапах |
| Winding number при вокселизации | CUDA при доступности, CPU fallback |
| Проекции строгой проверки и карты отклонений | CUDA при доступности, CPU fallback |
| Быстрое двустороннее измерение | Нативный CPU |
| 3D-отображение | VTK/OpenGL, независимо от CUDA |

CUDA-путь на физической RTX 3090 в этой работе не проверялся. В тестах проверены принудительный CPU и ошибки CUDA с fallback; журнал предназначен для сравнения на реальном оборудовании.

## Разработка, CLI и CI

```text
python -m meshrepair.worker input.stl --quality 0.02 --no-cuda --simplify-curved
python -m meshrepair.worker input.stl --quality 0.02 --output repaired.stl
python -m meshrepair.worker input.stl --check
python -m meshrepair.worker input.stl --preview-output view.npz
python -m meshrepair.worker input.stl --strict-tolerance --collapse-coplanar
python -m meshrepair.worker input.stl --temp-directory R:/MeshRepairTemp --remove-small-shells
python -m pytest -q
python tests/benchmark_090.py --real tests/data/test.stl --one-cpu --json benchmark-090.json
python tests/benchmark_synthetic.py
```

Без `--output` worker возвращает пути временных артефактов и ничего не публикует рядом с исходником. При самостоятельном запуске worker передаёт владение папкой родительскому PID; её удаляет вызывающая сторона или очистка осиротевших заданий. GUI передаёт `--work-dir` и управляет сроком жизни сам. Явный **`--output` сохраняет прежний контракт**: новый STL, JSON и карту отклонения, отказ от перезаписи. Копирование на другой диск поддерживается; ошибка записи дополнения не удаляет уже опубликованный STL. `--result-file` задаёт отдельный JSON-канал, `--debug` включает traceback; stdout-протокол JSON-lines сохранён.

CI запускает тесты и benchmark на Linux и Windows, затем собирает и проверяет EXE. В этой среде выполнены 104 теста Linux/Qt offscreen; Windows-сборку и физическую CUDA должен подтвердить CI/целевой ПК. Проверки ABI `projection_arrays` остаются обязательными: несовместимая раскладка даёт `projection_layout_mismatch`.

Условия push/PR не изменены: `main` push и внешние PR, без дублирующей сборки внутренних PR. `release.yml` публикует проверенный архив точного коммита по версии/тегу `v0.9.0` и SHA256SUMS в Releases; теги не пересобирают EXE. Существующий релиз другим коммитом не перезаписывается. Ограничение 30 дней относится к промежуточным Actions artifacts, а Release assets остаются доступными.

## Дополнительная проверка выпуска

После удаления полостей единственная оставшаяся оболочка проверяется после каждого QEM-прохода.
Если поздний проход недопустим, сохраняется ранний проверенный результат. Масштаб поиска может
быть меньше 0,15. Подготовка оболочек выполняется один раз на поиск. Переход к упрощению по оболочкам при первом общем отказе сохранён.

Для больших воксельных объёмов применяется расчёт по слоям/частям. Единичные пересечения обычной
воксельной поверхности исправляются локально только с подтверждённым смещением ≤¼ шага и
сохранением оболочек. Подробности и ограничения: [проверка 1.0.0](docs/validation-1.0.0.md).

## Регрессия базового коммита 49bbc1e

Сфера UV 200×200, R=5 мм: дыры радиусов 1,5 и 0,8 мм плюс 40 малых с seed=2, шаг 0,05 мм. На CPU полный `engine.run` занял 3,50 с: 38 → 0 дыр, четыре условные заплатки, CutAndFill 23 → 0 пересекающихся граней, 76 904 треугольника, одна замкнутая оболочка. Максимальное отклонение поверхности от идеальной сферы — 0,03466 мм. Тест ограничивает всю поверхность: максимум радиуса по вершинам, минимум — расстоянием от центра до ближайшей точки треугольников; лимиты 0,05 мм и 30 с. Время зависит от оборудования.

Регрессионные тесты также проходят через `engine.run` для полного невалидного Sharpening, автоматического/отложенного повтора и отмены условных заплаток. CUDA winding проверяется на повторное использование через тот же нативный интерфейс; это не замер физической GPU. Нативная многопоточность сохранена, последовательные Python-циклы по граням не добавлены.

Внутренние PR запускают Linux/Windows тесты и сборку EXE до merge; push запускает их только на main. Публикация релиза использует только успешную сборку main соответствующего коммита. Отдельная проверка запрещает импорты `meshrepair` в автономном `tests/check_bundle.py`.

Сравнение на одном и том же `test.stl`, CPU без CUDA, шаг 0,02 мм, упрощение включено (одиночные последовательные замеры в одной среде):

| Доступные CPU-потоки | 0.9.0 (c373809) | база 49bbc1e | Треугольники в обеих версиях |
|---|---:|---:|---:|
| 1 | 6,00 с | 5,75 с | 36 946 |
| 3 | 4,68 с | 3,96 с | 36 894 |

Пересечений во всех четырёх результатах — 0. Замедления в этих запусках нет; это не статистический прогноз для другого оборудования. Разное число потоков нативного упрощения может давать разную триангуляцию. Сфера на одном CPU: 5,06 с, отклонение всей поверхности 0,03466 мм. Числа сохранены в `tests/benchmark_091_results.json`. Для повторения сферы: `python -m pytest -q -s tests/test_release_091.py::test_uv_sphere_local_patches_surface_and_cpu_time`; ограничение CPU задаётся средствами ОС.

## Повторное упрощение и запуск без терминала

На `test.stl` (209 466 граней после локального ремонта), допуск 0,02 мм, один CPU без CUDA: **26 826 треугольников**, **11,34 с на упрощение вместе со строгой проверкой**, верхняя граница отклонения всей поверхности **0,0199999563 мм**. Это одиночный замер в среде разработки; тест требует ≤29 000 граней и <15 с упрощения на одном CPU. Проходы одного кандидата используют результаты предыдущего, но проверка всегда сравнивает итог с исходной исправленной сеткой.

В отчёте «Где остались треугольники» показаны крупные кластеры нормалей ±8° площадью >3 мм² и остальная поверхность. Это ограниченная по объёму вычислений оценка, а не сертификат плоскостности: плоскости могут содержать слабый шум и изгиб. Для исходных вершин, спроецированных на соответствующие участки результата, выводятся остатки от плоскости p50/p90. При p90 выше допуска отчёт объясняет, почему неровность мешает удалить полигоны. Эвристическая подсказка «допуск ×2,5 → примерно −25% треугольников» не запускает перерасчёт и не обещает такой результат для любой модели.

Windows-сборка — один `MeshRepair.exe` с GUI subsystem (`PyInstaller --windowed`). `start.cmd` устанавливает зависимости в консоли, затем запускает `pythonw.exe` и завершается. При запуске исходников из GUI используется `pythonw.exe`; где PySide6 предоставляет модификатор создания процесса, дополнительно задан `CREATE_NO_WINDOW`.

Ранний журнал: `%LOCALAPPDATA%\MeshRepair\logs\meshrepair.log`, три архивных файла, ротация при следующем запуске GUI после достижения 5 МиБ. Python-ошибки и faulthandler пишут в журнал; необработанная ошибка GUI показывает окно с путём к нему. Worker передаёт JSON-строки через `--progress-file` с flush после каждого события, GUI дочитывает их каждые 200 мс с сохранением смещения и неполной строки. Итог по-прежнему передаётся атомарным `--result-file`. CLI сохраняет stdout/stderr, если потоки доступны. Windows CI проверяет PE Subsystem=2, отсутствие консольного окна в smoke-запуске и реальные worker-операции без чтения stdout.
