# MeshRepair 0.1.0

Отдельное Windows-приложение для проверки и экспериментального ремонта ювелирных сеток.
Русский интерфейс, нативное C++-ядро MeshLib, многопоточные операции библиотеки и CUDA для поддерживаемой части объёмного расчёта. C++ и C# компилировать вручную **не требуется**.

**Это первая проверочная версия, не готовая замена Netfabb.** Сейчас реализованы диагностика и полное объёмное перестроение. Бережный локальный ремонт, строгая сертификация допуска и испытания на 10 млн треугольников — следующие этапы.

## Самый простой запуск: готовая сборка

1. Откройте [Actions](https://github.com/modeco46/MeshRepair/actions).
2. Выберите последний успешный `Check and build Windows app` (зелёная галочка).
3. Внизу в **Artifacts** скачайте `MeshRepair-0.1.0-windows-x64`. Для скачивания нужен вход в GitHub.
4. Распакуйте **весь** ZIP в отдельную папку на локальном NTFS-диске.
5. Запустите `MeshRepair.exe`. Папка `_internal` должна оставаться рядом.

Для этой сборки Python и компиляторы не нужны. В 0.1 рядом с интерфейсом может открываться консоль — не закрывайте её во время работы. Сборка не подписана цифровой подписью. Если успешной сборки пока нет, используйте запуск из исходников ниже.

## Запуск из исходников — тоже без компиляции

1. Один раз установите **Python 3.12, Windows installer (64-bit)** с [python.org](https://www.python.org/downloads/windows/). Оставьте включённой установку **Python Launcher** и Tcl/Tk.
2. На странице репозитория нажмите **Code → Download ZIP**.
3. Распакуйте архив в отдельную папку.
4. Дважды нажмите `start.cmd`. Он создаст локальное окружение `.venv` и установит готовые бинарные пакеты. Нужен интернет при первой установке.
5. Дождитесь окна приложения. Если запуск не удался, окно с текстом ошибки останется открытым.

Python используется только для интерфейса и управления. Тяжёлые операции выполняются внутри MeshLib. Visual Studio, CUDA Toolkit и сборка C++ не нужны. Для GPU нужен совместимый NVIDIA-драйвер; доступность определяется при запуске операции.

## Работа с программой

1. Выберите STL, OBJ или PLY. Выходной формат в 0.1 — STL.
2. Убедитесь, что единицы исходного файла — **миллиметры**, и поставьте соответствующую галочку. STL не хранит единицы. Программа не угадывает масштаб.
3. Нажмите **Проверить сетку** для диагностики.
4. Укажите новое имя результата, например `ring_candidate.stl`.
5. Задайте целевой допуск **0,001–0,02 мм**. Можно вводить запятую.
6. Выберите **Авто**, **CPU** или **CUDA**.
7. Нажмите **Построить кандидата**. Результат и отчёт `ring_candidate.stl.json` будут рядом.
8. Проверьте геометрию результата в Rhino. Пока встроенного 3D-просмотра нет.

В режиме «Авто» CUDA используется при доступности и прохождении предварительной проверки VRAM, иначе CPU; причина записывается в отчёт. При явном выборе CUDA её недоступность вызывает ошибку, без скрытого переключения. Успешный запуск CUDA означает ускорение winding-number этапа, а не всей цепочки.

Если выбрано «Требовать одну связную оболочку», раздельные части не удаляются и не соединяются автоматически: результат с несколькими компонентами отклоняется. Без этой галочки несколько замкнутых оболочек разрешены. Полые тела с отдельными внутренними оболочками требуют такого режима и ручной проверки.

## Что означает точность

- Введённое значение — **целевой допуск**, не доказанная гарантия.
- Начальный шаг перестроения равен половине допуска. Это эвристика, не доказательство ошибки.
- Проверяется максимум расстояний **от вершин обеих сеток до поверхности другой**. Это не непрерывное расстояние Хаусдорфа: отклонения внутри треугольников могут быть пропущены.
- `tolerance_certified` всегда `false` в 0.1, даже если оценка уложилась в допуск.
- При превышении допуска кандидат сохраняется с явным предупреждением и статусом `candidate_exceeds_tolerance`.
- Новые заплатки и удалённые внутренние поверхности могут закономерно давать большое отклонение. Они пока не выделяются отдельно.
- Грубое закрытие дыр, смешанная ориентация открытых оболочек, тонкие элементы и острые кромки могут давать неверную форму при формально замкнутой сетке.
- Входные/выходные координаты MeshLib/STL имеют конечную точность. Перенос расчёта ближе к нулю не восстанавливает точность, уже потерянную при загрузке большого смещения.

Не используйте кандидат для производства только на основании статуса «замкнута».

## Память и скорость

Нативные алгоритмы MeshLib используют многопоточность там, где она реализована. Число потоков пока определяется библиотекой. Проверка и ремонт выполняются в отдельном процессе, интерфейс не блокируется; «Отмена» завершает этот процесс.

Перед перестроением оценивается размер ограничивающего воксельного объёма. В интерфейсе лимит **100 млн ячеек**. Это ограничение объёма работы, **не строгий лимит памяти**. В отчёте размер одного float-поля — только базовая оценка; реальные промежуточные данные занимают больше. Диагностика самопересечений также может требовать много памяти.

В CPU-режиме запрошен `memoryEfficient`; при CUDA этот режим библиотека игнорирует. До CUDA сравнивается консервативная оценка с доступной VRAM. При ошибке непосредственно во время GPU-расчёта версия 0.1 останавливается, а не запускает молча повторную тяжёлую операцию.

Большая ювелирная модель при допуске 0,001 мм может быть отклонена по лимиту. Программа **не ухудшает точность автоматически**. Для больших моделей нужен будущий бережный/локальный ремонт; полное воксельное перестроение не масштабируется произвольно. Скорость на 10 млн треугольников пока не измерена.

## Сохранение и отмена

Исходники не перезаписываются. Перед публикацией кандидат полностью записывается во временный файл; для публикации без перезаписи используется hard link. Выходная папка должна поддерживать hard links (локальный NTFS на Windows); FAT32/exFAT не подходят для этой версии. Отчёт записывается отдельно после mesh: при отмене в короткий момент публикации может остаться полный STL без JSON — он не считается проверенным результатом приложения. После отмены могут остаться временные `.meshrepair-*` файлы; их можно удалить.

## Командная строка (для разработчика)

```text
python -m meshrepair.worker input.stl
python -m meshrepair.worker input.stl --output candidate.stl --tolerance 0.01 --device auto
python -m pytest -q
```

Дополнительные параметры: `--allow-components`, `--max-grid-cells`. Увеличение лимита ячеек требует оценки RAM/VRAM и времени; это не обход ограничений оборудования.
