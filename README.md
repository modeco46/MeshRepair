# MeshRepair 0.2.0

Windows-приложение для диагностики и ремонта ювелирных сеток. Русский интерфейс, C++-ядро MeshLib через Python. Компиляция C++/C# и установка Python для готового EXE **не нужны**.

## Скачать и запустить

1. Откройте [Actions](https://github.com/modeco46/MeshRepair/actions) → последний успешный **Check and build Windows app**.
2. Внизу, в **Artifacts**, скачайте **MeshRepair-0.2.0-windows-x64** (нужен вход в GitHub).
3. Распакуйте весь ZIP в новую папку на локальном NTFS-диске.
4. Запустите `MeshRepair.exe`. Сохраните рядом `_internal`. Консоль рядом с окном — нормальное поведение версии 0.2; не закрывайте её во время расчёта.

Альтернатива: установите [Python 3.12 x64](https://www.python.org/downloads/windows/) с Python Launcher и Tcl/Tk, скачайте **Code → Download ZIP**, распакуйте и запустите `start.cmd`. Готовые пакеты устанавливаются автоматически через интернет, компилятор не нужен.

## Что исправлено после 0.1

- По умолчанию работает **бережный метод по треугольникам**, а не полное воксельное перестроение.
- Исправная замкнутая сетка без пересечений не ремешится.
- **Объединение тел** выполняет последовательные булевы объединения оболочек, не ограничиваясь 100 млн вокселей.
- Воксельный метод остался отдельным, явно выбираемым режимом. Автоматического перехода к нему нет.
- Понятные сообщения вместо traceback; технический стек доступен через `--debug` в CLI.
- В интерфейсе есть **лимит времени**, по умолчанию **180 секунд**. Это остановка процесса, а не обещание успеть за 3 минуты.
- Отдельная настройка максимально разрешённого **периметра закрываемых дыр**, по умолчанию 1 мм.

## Какой метод выбрать

| Метод | Назначение и ограничения |
|---|---|
| **Бережный** | Сохраняет исправные оболочки, закрывает разрешённые дырки, пробует экспериментальный `selfBoolean` при пересечениях. Не выполняет глобальное сглаживание/ремеш. Если сложные пересечения остаются — останавливается. |
| **Объединение тел** | Рассматривает каждую оболочку как сплошное тело и делает булево объединение. Обрабатывает пересекающиеся и вложенные тела. **Удаляет внутренние полости**, поэтому не подходит для сохранения полого изделия. |
| **Воксельный** | Полное перестроение через поле расстояний. Может изменить детали; дороже по времени и памяти, особенно при 0,001 мм. Использовать отдельно для тяжёлых случаев. |

Если исходник замкнут, без пересечений, но содержит 3 оболочки:

- это не обязательно повреждение;
- бережный режим сохранит оболочки;
- объединение может убрать вложенные оболочки или объединить пересекающиеся тела;
- **разнесённые в пространстве тела не станут одной оболочкой без добавления геометрии**. Перемычки автоматически не создаются, части не удаляются;
- отключение «Требовать одну связную оболочку» разрешает сохранить несколько оболочек. Иначе программа объяснит причину остановки.

## Работа

1. Выберите STL, OBJ или PLY. Выход — новый STL; существующие файлы не перезаписываются.
2. Подтвердите, что координаты заданы в **миллиметрах**. STL не хранит единицы; масштаб не угадывается.
3. Выберите метод, целевой допуск **0,001–0,02 мм**, допустимый периметр дыр и лимит времени.
4. Нажмите **Проверить сетку** или **Построить кандидата**.
5. Откройте результат в Rhino и прочитайте JSON-отчёт рядом с STL. Встроенного 3D-просмотра пока нет.

Дыры большего разрешённого периметра не закрываются молча. При загрузке с пропущенными гранями ремонт останавливается. При более чем 256 компонентах поверхностный режим останавливается, чтобы не создавать огромное число промежуточных битовых масок.

## CPU, GPU и время

Поверхностные операции выполняются нативным CPU-ядром с многопоточностью там, где она реализована MeshLib. Не все этапы параллельны; число потоков пока задаётся библиотекой. **CUDA используется только для поддерживаемого winding-number этапа воксельного метода**, не для всей цепочки. Выбор CUDA вместе с поверхностным методом явно сообщает, что используется CPU.

В режиме «Авто» воксельный расчёт выбирает доступную CUDA с предварительной проверкой VRAM, иначе CPU; причина записывается в отчёт. При явном выборе CUDA её недоступность вызывает ошибку. CUDA Toolkit не требуется, нужен совместимый драйвер NVIDIA. Вычисления на пользовательской RTX 3090 ещё не испытаны.

**338 тысяч треугольников недостаточно для прогноза времени.** Важны количество и структура пересечений, число оболочек, геометрия дыр, CPU/RAM. Поверхностный метод позволяет избежать миллиардов ячеек; 2–3 минуты — целевой бюджет, не универсальная гарантия.

Лимит **100 млн ячеек** относится исключительно к воксельному методу и не является лимитом полигонов или строгим лимитом RAM. Увеличить его можно через CLI `--max-grid-cells`, но это только разрешает больший расчёт, не ускоряет его. Полный объём примерно растёт как обратный куб шага. Уменьшение шага вдвое даёт около 8 раз больше ячеек; реальное время не обязано вырасти ровно в 8 раз. При CUDA настройка `memoryEfficient` игнорируется библиотекой. Один float на ячейку — только нижняя оценка данных, промежуточных структур больше.

Лимит времени интерфейса распространяется на диагностику, ремонт, проверку и сохранение. Нажатие «Отмена» или истечение лимита завершает рабочий процесс. Для больших моделей можно увеличить число секунд. CLI сам по себе не имеет watchdog — его вызывающая программа должна задавать timeout (как в benchmark-скрипте).

## Точность и ограничения

- Допуск — цель, **не доказанная гарантия**. `tolerance_certified` всегда `false`.
- В поверхностном методе допуск используется для итоговой оценки, а не для глобального смещения/сварки вершин. Для исправного исходника геометрия в рабочем пространстве сохраняется; экспорт STL имеет конечную точность.
- Проверяется максимум расстояний от вершин обеих сеток к поверхности другой, **не непрерывное расстояние Хаусдорфа**. Между вершинами могут быть большие отклонения.
- При превышении допуска сохраняется только кандидат с явным предупреждением, не «годная производственная модель».
- Удалённые внутренние поверхности и новые заплатки могут давать большое отклонение. Они пока не исключаются из оценки и не выделяются отдельно.
- В воксельном режиме шаг равен половине допуска, но это не доказывает точность результата.
- Экспериментальный `selfBoolean` не гарантирует исправление произвольной геометрии. Проверка топологии/пересечений после него обязательна, но не подтверждает замысел модели.
- Перенос координат ближе к нулю не восстанавливает точность, потерянную при загрузке. Строгий контроль погрешности после экспорта пока не реализован.
- Сложные смешанные нормали, неманифолдные/вырожденные исходные данные и очень тонкие детали могут требовать отдельной обработки. Это проверочная версия, а не обещание исправить любой STL.

## Безопасное сохранение

Исходники не изменяются. Кандидат записывается во временный файл и публикуется без перезаписи через hard link. Нужна папка с поддержкой hard links (локальный NTFS); FAT32/exFAT не подходят. Отчёт записывается отдельно после STL. Если отменить в этот короткий момент, может остаться полный STL без JSON — его нельзя считать завершённым результатом. Временные `.meshrepair-*` файлы после отмены можно удалить.

## Команды разработчика

```text
python -m meshrepair.worker input.stl
python -m meshrepair.worker input.stl --output candidate.stl --method union --tolerance 0.01
python -m meshrepair.worker input.stl --output candidate.stl --method voxel --device auto
python -m pytest -q
python tests/benchmark_synthetic.py
```

Другие параметры: `--allow-components`, `--max-hole-perimeter`, `--max-grid-cells`, `--debug`.
