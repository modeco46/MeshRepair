# MeshRepair 0.8.0

Автоматическое исправление ювелирных сеток. **Выберите файл → задайте качество → нажмите «Исправить».**

## Скачать и запустить

1. Откройте [Releases](https://github.com/modeco46/MeshRepair/releases) → последний выпуск.
2. В **Assets** скачайте **MeshRepair-0.8.0-windows-x64.zip**. Полные исходники — **Source code (zip)**. До публикации релиза архив доступен в [Actions](https://github.com/modeco46/MeshRepair/actions).
3. Распакуйте весь ZIP в новую папку на локальном NTFS-диске.
4. Запустите `MeshRepair.exe`. Папка `_internal` должна оставаться рядом. Консоль не закрывайте во время работы.

Для готового EXE не нужны Python, Visual Studio, C++/C# компиляторы или CUDA Toolkit. Для CUDA нужен совместимый драйвер NVIDIA. Для 3D-окна нужен OpenGL 3.2 или новее; отображение и CUDA — разные подсистемы.

Из исходников: установите [Python 3.12 x64](https://www.python.org/downloads/windows/) с Python Launcher, скачайте **Code → Download ZIP**, распакуйте и запустите `start.cmd`. Бинарные зависимости устанавливаются автоматически через интернет.

## Интерфейс

- **Исходная сетка:** STL, OBJ или PLY. Можно выбрать файл, нажать Ctrl+O или перетащить файл из Проводника в окно.
- **3D-предпросмотр:** вращение ЛКМ, сдвиг СКМ, масштаб колесом. Кнопки «Поверхность» и «Рёбра» работают независимо: сплошная модель, каркас или поверхность с рёбрами. Есть вписывание и виды сверху/спереди/изометрия. После ремонта доступны переключатели «Исходник» и «Результат».
- **Check / Проверить:** полная диагностика отображаемого файла без ремонта и сохранения нового STL. Если открыт результат, проверяется результат; кнопка ремонта всегда работает с выбранным исходником.
- **Качество / допуск:** от **0,001 до 0,5 мм**, запятая и точка разрешены. Меньше — подробнее и обычно дольше; больше — грубее и обычно быстрее.
- **Схлопывать копланарные полигоны:** необязательный флажок, угол от **0 до 45°**, по умолчанию **1°**. Угол задаёт порог разницы нормалей соседних граней исходной для этого этапа сетки; больше — больше участков разрешено упрощать. Численный допуск в миллиметрах при этом сохраняется.
- **Упрощать всю поверхность в пределах допуска:** адаптивное уменьшение числа треугольников на плоскостях и криволинейных участках за один проход. При включении угол копланарности не применяется и его поле отключается. Обе опции изначально выключены.
- **Исправить:** запускает всю обработку и сохраняет результат.
- **Остановить:** завершает рабочий процесс в любой момент. Автоматического таймера остановки нет.
- **Прогресс:** проценты и текущий этап; рядом прошедшее время. Проценты отражают этапы и callbacks библиотеки, не прогноз оставшегося времени. Долгий этап может некоторое время оставаться на одном проценте.
- **Журнал:** выделение текста и Ctrl+C, стандартное контекстное меню, кнопки «Копировать» и «Очистить». «Копировать» копирует выделение, а при отсутствии выделения — весь журнал. Очистка не изменяет сетку или JSON-отчёт.

Интерфейс переведён на Qt. Качество, угол и флажки запоминаются между запусками. Настройки прокручиваются в небольшом окне; кнопки ремонта и остановки остаются доступными.

Миллиметры используются всегда. Алгоритм ремонта и доступное ускорение выбираются автоматически, подтверждения единиц и лимита времени нет. Результат сохраняется рядом с исходником как `имя_repaired.stl`, затем `имя_repaired_1.stl` и т. д. Существующие файлы не перезаписываются. Подробный JSON-отчёт сохраняется рядом.

## Диагностика и предпросмотр

При открытии показываются базовые сведения. Карточка **«Связные части»** считает фрагменты топологии после загрузки, а не физические тела и не число вывернутых граней. MeshLib может отделять участки с несогласованной ориентацией, дублируя вершины. Поэтому 2149 частей не обязательно означает 2149 отдельных деталей.

**Check** проверяет исходник и пробует согласование ориентации на отдельной копии. Файл и отображаемый исходник не изменяются. Вкладка **«Отчёт»** показывает исходные дефекты, число несогласованных рёбер, части до/после согласования, шаги ремонта с временем, выбор алгоритма, результат, отклонение, попытки упрощения и причины отказа. В журнале остаётся краткий ход операции. После ремонта карточки результата показывают «до → после».

В таблице оболочек указаны замкнутость, открытые рёбра, габариты bbox в мм и тип (основное тело / мелкий остров). Таблица ограничена 2000 крупнейшими частями, общая статистика включает все. «Основное тело» — часть с наибольшим числом треугольников, а не гарантированно наибольшим объёмом.


Предпросмотр показывает **все треугольники**, без скрытого упрощения. Геометрия переносится к центру сцены только для отображения. Загрузка и подготовка выполняются вне потока интерфейса; временный файл предпросмотра удаляется после чтения. На 10 млн треугольников нужны соответствующие RAM/VRAM; включение рёбер дополнительно нагружает отображение. Финальная передача большой модели в видеодрайвер может временно задержать интерфейс.

## Как работает автоматический ремонт

1. Загрузка, проверка NaN/inf, точная склейка и согласование ориентации. Затем диагностика и пересчёт связности.
2. Заполнение простых дыр при любом числе оболочек/дыр. Плоские заплатки триангулируются без сглаживания, остальные — через `fillHoleNicely` с восстановлением кривизны. Каждая заплатка проверяется отдельно и полностью откатывается при новом дефекте.
3. Если остались пересечения или открытые фрагменты — **разреженное восстановление OpenVDB**. Флажок **«Восстанавливать острые рёбра»** включён по умолчанию: используется `generalOffsetMesh` в режиме Sharpening. При ошибке или невалидной топологии — обычный `offsetMesh` с тем же шагом и явным предупреждением.
4. Проверка результата, очистка вырожденных треугольников после восстановления, запись STL.
5. **Повторное чтение и проверка самого сохранённого STL** на замкнутость, валидность топологии и самопересечения.
6. При включённых флажках — упрощение, повторная запись и проверка STL. Результат упрощения принимается только после проверки отклонения и топологии. Затем публикация результата и 100%.

Порог 32 больше не ограничивает заполнение дыр; он оставлен только для последовательного булева объединения уже замкнутых тел без самопересечений. Прежних запретов «больше 256 оболочек» и «больше 100 млн ячеек» нет. Восстановление использует разреженную полосу около поверхности вместо плотного заполнения всего габаритного параллелепипеда.

Частично испорченные при загрузке грани могут быть пропущены загрузчиком; число записывается в отчёт и показывается в предупреждении. Если нет пригодных треугольников, восстановить форму невозможно.

## Уменьшение числа треугольников

В отдельном схлопывании плоскостей координаты оставшихся вершин не оптимизируются. Порог угла выделяет резкие переходы: фиксируются углы и развилки, а промежуточные вершины почти прямого ребра могут удаляться. Общее упрощение обрабатывает всю поверхность с оптимизацией координат и угловым взвешиванием квадратичной ошибки, без фиксации каждого резкого ребра воксельной сетки. Если включены оба флажка, выполняется один общий проход: два последовательных прохода расходовали бы допуск повторно. STL всегда состоит из треугольников: приложение уменьшает их число, а не сохраняет многоугольники с произвольным количеством сторон.

**Допуск упрощения отсчитывается от уже исправленной сетки до упрощения.** Например, при 0,02 мм проверяется, что дополнительное отклонение от этой поверхности не превышает 0,02 мм. Это не ограничение суммарного отклонения ремонта от повреждённого исходника.

Оценка ошибки нативного алгоритма сама по себе недостаточна. Поэтому проверяется именно записанный и заново загруженный STL: вычисляется консервативная верхняя граница расстояния **в обе стороны по всей поверхности треугольников**, с адаптивным разбиением неоднозначных участков. Соседние грани с выпуклой общей проекцией проверяются вместе, с учётом высоты их сгиба: это уменьшает лишнее разбиение около внутренних рёбер плоских участков. Строгая проверка не ограничивается вершинами или случайными точками. При выключенной строгой галочке допускается явно отмеченный режим измерения по вершинам, описанный ниже. Вычисления используют float64 и численный запас; это не доказательство в точной арифметике.

Если подтверждение допуска не удалось, выполняются дополнительные попытки; поведение строгого и измеренного режимов описано ниже. Изменение числа оболочек и дефекты топологии всегда отклоняют кандидата. Процент уменьшения не задан заранее: он зависит от формы и допуска. В журнале выводится число треугольников до и после; в JSON — блок `simplification` с результатом проверки.

## Что считается результатом

Сохраняется один STL с замкнутыми поверхностями без обнаруженных самопересечений. Пересекающиеся/вложенные оболочки по возможности объединяются. Обработка как сплошных тел **может удалить внутренние полости**.

Если детали физически разнесены, файл может содержать несколько замкнутых оболочек: приложение **сохранит их и явно сообщит число**, а не откажет в сохранении. Перемычки не добавляются, отдельные детали не удаляются специально. Один STL не всегда означает одно связное тело. Элементы меньше выбранного разрешения могут исчезнуть при восстановлении; проверяйте форму.

Программа не может гарантировать корректную реконструкцию любой произвольно повреждённой геометрии. Восстановление по дырявым поверхностям/смешанным нормалям неоднозначно. Если результат не прошёл финальную проверку, повреждённый STL не выдаётся как успешный результат. Проверьте форму в Rhino перед изготовлением.

## Значение качества

В объёмном восстановлении качество задаёт **шаг вокселя в миллиметрах**. В поверхностном ремонте исправная геометрия сохраняется; она не упрощается принудительно ради более грубого выбранного качества.

Это **не сертифицированное максимальное отклонение всего ремонта от исходника**. `tolerance_certified` в отчёте всегда `false`. Заплатки, удалённые внутренние оболочки и восстановление могут отклоняться от исходника сильнее шага. Очистка вырожденных граней использует отдельный малый допуск 1% шага. Отдельная проверка `simplification.verification` относится только к дополнительному упрощению относительно исправленной сетки. STL/нативные координаты имеют конечную численную точность.

## Скорость и память

C++-ядро MeshLib использует многопоточность на поддерживаемых этапах. Распределение в этой версии:

| Этап | Ускорение |
| --- | --- |
| Определение внутреннего объёма при разреженном восстановлении | CUDA FastWindingNumber; при недоступности/ошибке — CPU |
| Поиск ближайших граней для проверки допуска упрощения | CUDA PointsToMeshProjector; при недоступности/ошибке — CPU |
| Проверка геометрических верхних границ расстояния | Пакетные вычисления float64 на CPU; точность не подменяется оценкой CUDA |
| Decimation крупных сеток | Нативное параллельное разбиение; число частей зависит от числа доступных CPU и размера сетки, прежнего ограничения восемью частями нет |
| Булевы операции, топология, поиск пересечений, OpenVDB | Нативные CPU-алгоритмы, многопоточность там, где её реализует SDK |
| 3D-поверхность и рёбра | VTK / OpenGL через доступный видеодрайвер |

У используемого SDK нет CUDA-реализаций всех операций. Приложение не заявляет, что весь ремонт перенесён на GPU. Доступность CUDA видна в шапке; устройство отображения и выбор CPU/CUDA для проекций выводятся в журнал, сведения об ускорении — в JSON. Программный OpenGL-драйвер также возможен: его название показывается без ложного обозначения аппаратным GPU. При ошибке CUDA точность не снижается.

Упрощение выполняется на CPU, для сеток от 50 тысяч граней — с разбиением на части для параллельной обработки. Во время параллельного схлопывания показываются начало и конец этапа: Python-callback прогресса в закреплённой версии SDK вызывает взаимную блокировку потоков и здесь отключён. Кнопка остановки продолжает работать. Дополнительная проверка отклонения требует времени и памяти; на сложных сетках и малом допуске она может занять больше времени, чем сам ремонт.

Размер плотного объёма больше не служит причиной отказа, но разреженные данные также могут быть огромными. **0,001 мм на крупной модели может потребовать много времени и RAM.** Программа не снижает качество скрыто. Пользователь может остановить расчёт и выбрать более грубое качество. Реальная скорость зависит не только от числа треугольников, но и от площади, разрешения, дыр и структуры пересечений. Обещания «любой mesh за 2–3 минуты» нет.

В репозитории есть тест с 1150 открытыми оболочками и benchmark объединения 338 тысяч треугольников. Эти искусственные модели не заменяют испытания реальных `444.stl` и `bl2rh.obj`; сами эти файлы для разработки пока не предоставлены. Работа GPU на пользовательской RTX 3090 также не проверена.

## Отмена и сохранение

Тяжёлая работа выполняется в отдельном процессе, поэтому интерфейс и остановка не зависят от блокирующего вызова C++. После остановки GUI удаляет временную папку своего задания. После аварии всего приложения или принудительного завершения CLI папка может остаться — её можно удалить. В короткий момент публикации может остаться полный STL без JSON; это не завершённый отчёт приложения.

Результат публикуется без перезаписи: на Windows используется rename, на POSIX hard link. Требование hard links для Windows снято. Исходник не меняется.

```text
python -m meshrepair.worker input.stl --quality 0.02
python -m meshrepair.worker input.stl --check
python -m meshrepair.worker input.stl --preview-output view.npz
```

## Исправления 0.6.0: ориентация и отчёт

Перед диагностикой и выбором алгоритма выполняются точная склейка совпадающих координат и согласование порядка вершин соседних граней. Граф чётности решается в нативном SciPy без Python-обхода каждой грани. Неманифолдные рёбра не используются для переноса ориентации; противоречивый граф явно отмечается в отчёте. Число `disoriented_edges` — количество рёбер с одинаковым направлением у двух соседних граней. Число развёрнутых граней не выдаётся за число ошибок.

Для замкнутых компонент направление выбирается отдельно по собственному знаку объёма. Для открытых используется согласование с сохранением большинства исходной площади — это эвристика, не доказательство внешней стороны. Перед winding-восстановлением дополнительно проверяется ориентация замкнутых компонент. Общий знак объёма всей открытой сетки не используется.

Раздельные замкнутые тела без пересечений при числе >32 сохраняются без вокселизации. При ремонте только нормалей координаты и треугольники сохраняются; лишние заплатки на месте перевёрнутых участков не создаются. Если нужны дыры/пересечения/булево объединение, последующие этапы по-прежнему могут менять геометрию. Дополнительная галочка **«Склеивать близкие вершины»** использует 0,1 × качество; по умолчанию выключена и отражена в JSON.

### Упрощение и смысл допуска

В 0.7 доступны три попытки с `maxError = качество`, затем ×0,5 и ×0,25. Это лишь оценка нативного алгоритма: принятие по-прежнему требует независимой проверки записанного STL. Каждая начинается от исправленной сетки, а не от уже отклонённого кандидата. Компоненты меньше 50 граней полностью исключаются из входа дециматора и добавляются обратно без изменения геометрии и связности. Сначала проверяется сохранение числа оболочек, замкнутость и отсутствие обнаруженных самопересечений.

**«Строго доказывать допуск» по умолчанию выключено.** Сначала выполняется ограниченная строгая численная проверка. Если она не завершилась из-за лимита работы, неоднозначности расстояния или сбоя проекций, допускается нативное двустороннее измерение расстояний от вершин к поверхности. Такой результат обозначается `mode=measured_not_proven`, `verified=false`: **это не гарантия максимального отклонения всей поверхности**. Реальное обнаруженное превышение допуска никогда не обходится этим режимом. При включённой строгой галочке принятие требует подтверждённой численной границы всей поверхности; при неудаче всех попыток сохраняется исправленная сетка без упрощения с русской причиной и кодом.

Строгая проверка строит смежность граней в NumPy один раз. Проекции читаются пакетно через проверяемый POD-layout закреплённой версии MeshLib; несовместимая раскладка немедленно вызывает понятную ошибку `projection_layout_mismatch`, без скрытого перехода на медленный Python-цикл. Это устраняет Python-цикл по проекциям и повторные обходы `leftRing`.

После окончательного STL `Projector` измеряет расстояния всех вершин исходника до поверхности результата, с CUDA при доступности и CPU fallback. При отклонении >2 × шага выдаётся предупреждение о возможной потере деталей, изменении полостей или большой заплатке. Измерение одностороннее и по вершинам; оно не доказывает точность ремонта и может не увидеть добавленный пузырь, поэтому согласование ориентации выполняется **до** восстановления.

### Надёжность

Координаты NaN/inf вызывают понятную ошибку сразу после загрузки. Результат worker можно получить через `--result-file PATH`; без флага прежние JSON-строки `result/error` сохраняются. GUI использует отдельный файл для окончательного отчёта и раздельные stdout/stderr. Прогресс и журнал остаются JSON-строками.

Временные STL и JSON находятся в собственной подпапке задания `.meshrepair-*`. После остановки GUI удаляет только свою папку, не затрагивая другие запуски. На Windows результат публикуется `os.rename` без перезаписи; на POSIX — `os.link`. NaN/inf в диагностическом отчёте преобразуются в `null`; ошибка записи JSON не удаляет успешно сохранённый STL.

Тесты включают куб 10 мм / 12288 граней с перевёрнутым патчем и 60 раздельными патчами, 40 кубов с 13 обратными оболочками, NaN, строгий отказ и измеренный fallback, защиту мелких островов, очистку после Stop и отдельный канал результата. Тест ориентации сферы из 720000 граней проверяет время <5 с в CI; это не обещание такого времени на любом ПК. Сборка EXE отдельно проверяет SciPy, перевёрнутые патчи, упрощение, Qt/VTK и файловый канал.

## Изменения 0.8.0

- Конфликт ориентации ограничен неориентируемой компонентой двойного накрытия. Её грани сохраняют исходный порядок; остальные компоненты согласуются. Число пропущенных компонентов и граней видно в отчёте.
- Безопасное заполнение дыр предшествует выбору алгоритма независимо от числа дыр. Ограничения одной дыры: диагональ bbox ≤10 мм, ≤2048 рёбер, оценка/размер заплатки ≤50000 граней, ≤20000 разделений рёбер. Бюджет этапа — 60 с между вызовами SDK; один нативный вызов ограничен объёмом работы, но это не жёсткий таймер. Пропуски и откаты записываются в отчёт; оставшиеся дыры обрабатывает воксельный метод.
- Sharpening по умолчанию включён и сохраняется в настройках. CLI: `--no-restore-sharp-edges` отключает его, прежние JSON-строки worker сохранены. `fwn` и `callBack` используются; ошибки CUDA повторяются на CPU, ошибки Sharpening — обычным ремешем.
- Рядом со STL и JSON сохраняется `.stl.deviation.npz`: мировые координаты всех вершин исходника, расстояния и порог двух шагов. JSON содержит только максимум, число превышений и топ-10 точек. Кнопка **«Отклонения»** показывает карту: синий — ноль, жёлтый — два шага, красный — больше двух шагов. Карта выравнивается с исходником и результатом с учётом их разных центров предпросмотра. Включение карты расходует дополнительную RAM/VRAM.
- Карта односторонняя: она помогает найти потерянные детали, но может не заметить добавленные шипы и дефекты внутри заплаток. Sharpening на шуме и тонких стенках не гарантирует улучшения. Предупреждение >2×шага сохраняется всегда.

Клин построен булевым объединением двух плит 12×8×3 мм под 120°, повёрнут на 23° вокруг (1,1,0.3); после подразделения удалены 45 раздельных треугольников. ### Сборка и постоянные релизы

`check.yml` тестирует и собирает только push в `main` и pull request в `main` из форка. Внутренний PR не запускает повторную сборку. Теги не пересобирают EXE.

После успешной сборки `main` новая версия из `meshrepair/__init__.py` получает тег `vX.Y.Z`, если такого тега ещё нет. `release.yml` публикует **уже проверенный архив именно этого коммита** и `SHA256SUMS.txt` в GitHub Releases. Он также поддерживает вручную созданный тег. Если версия уже выпущена другим коммитом, тег и файлы не перезаписываются: для следующего релиза нужно изменить версию. Артефакты PR и неуспешных сборок не публикуются. ZIP полного кода доступен в стандартных Source code релиза. Срок 30 дней относится только к промежуточному Actions artifact, а не к Release assets.
