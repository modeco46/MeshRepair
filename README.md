# MeshRepair 0.4.0

Автоматическое исправление ювелирных сеток. **Выберите файл → задайте качество → нажмите «Исправить».**

## Скачать и запустить

1. Откройте [Actions](https://github.com/modeco46/MeshRepair/actions) → последний успешный **Check and build Windows app**.
2. Внизу в **Artifacts** скачайте **MeshRepair-0.4.0-windows-x64** (нужен вход в GitHub).
3. Распакуйте весь ZIP в новую папку на локальном NTFS-диске.
4. Запустите `MeshRepair.exe`. Папка `_internal` должна оставаться рядом. Консоль не закрывайте во время работы.

Для готового EXE не нужны Python, Visual Studio, C++/C# компиляторы или CUDA Toolkit. Для GPU нужен совместимый драйвер NVIDIA.

Из исходников: установите [Python 3.12 x64](https://www.python.org/downloads/windows/) с Python Launcher и Tcl/Tk, скачайте **Code → Download ZIP**, распакуйте и запустите `start.cmd`. Бинарные зависимости устанавливаются автоматически через интернет.

## Интерфейс

- **Исходная сетка:** STL, OBJ или PLY.
- **Качество / допуск:** от **0,001 до 0,5 мм**, запятая и точка разрешены. Меньше — подробнее и обычно дольше; больше — грубее и обычно быстрее.
- **Схлопывать копланарные полигоны:** необязательный флажок, угол от **0 до 45°**, по умолчанию **1°**. Угол задаёт порог разницы нормалей соседних граней исходной для этого этапа сетки; больше — больше участков разрешено упрощать. Численный допуск в миллиметрах при этом сохраняется.
- **Упрощать криволинейные участки в пределах допуска:** дополнительное адаптивное уменьшение числа треугольников на плавных поверхностях. Обе опции можно включать независимо, изначально они выключены.
- **Исправить:** запускает всю обработку и сохраняет результат.
- **Остановить:** завершает рабочий процесс в любой момент. Автоматического таймера остановки нет.
- **Прогресс:** проценты и текущий этап; рядом прошедшее время. Проценты отражают этапы и callbacks библиотеки, не прогноз оставшегося времени. Долгий этап может некоторое время оставаться на одном проценте.

Миллиметры используются всегда. Режимов, выбора GPU, подтверждения единиц, лимита времени и отдельной кнопки диагностики нет. Результат сохраняется рядом с исходником как `имя_repaired.stl`, затем `имя_repaired_1.stl` и т. д. Существующие файлы не перезаписываются. Подробный JSON-отчёт сохраняется рядом.

## Как работает автоматический ремонт

1. Загрузка и проверка дыр, пересечений и связности.
2. Для небольшого числа оболочек/дыр — попытка заполнения дыр и булева объединения сплошных тел по треугольникам. Исправные поверхности не ремешатся без необходимости.
3. Для большого числа фрагментов или неудачи поверхностного ремонта — **разреженное восстановление OpenVDB** с определением внутреннего объёма через winding number.
4. Проверка результата, очистка вырожденных треугольников после восстановления, запись STL.
5. **Повторное чтение и проверка самого сохранённого STL** на замкнутость, валидность топологии и самопересечения.
6. При включённых флажках — упрощение, повторная запись и проверка STL. Результат упрощения принимается только после проверки отклонения и топологии. Затем публикация результата и 100%.

Порог 32 оболочки/дыры используется только для выбора алгоритма, **не для отказа**. Прежних запретов «больше 256 оболочек» и «больше 100 млн ячеек» нет. Восстановление использует разреженную полосу около поверхности вместо плотного заполнения всего габаритного параллелепипеда.

Частично испорченные при загрузке грани могут быть пропущены загрузчиком; число записывается в отчёт и показывается в предупреждении. Если нет пригодных треугольников, восстановить форму невозможно.

## Уменьшение числа треугольников

Плоские участки упрощаются схлопыванием рёбер без оптимизации координат оставшихся вершин. Границы резких переходов, выделенные выбранным углом, защищаются. Для криволинейных участков используется адаптивное схлопывание с оптимизацией положения вершин и защитой исходных рёбер с углом больше 30°. STL всегда состоит из треугольников: приложение уменьшает их число, а не сохраняет многоугольники с произвольным количеством сторон.

**Допуск упрощения отсчитывается от уже исправленной сетки до упрощения.** Например, при 0,02 мм проверяется, что дополнительное отклонение от этой поверхности не превышает 0,02 мм. Это не ограничение суммарного отклонения ремонта от повреждённого исходника.

Оценка ошибки нативного алгоритма сама по себе недостаточна. Поэтому проверяется именно записанный и заново загруженный STL: вычисляется консервативная верхняя граница расстояния **в обе стороны по всей поверхности треугольников**, с адаптивным разбиением неоднозначных участков. Соседние грани с выпуклой общей проекцией проверяются вместе, с учётом высоты их сгиба: это уменьшает лишнее разбиение около внутренних рёбер плоских участков. Проверка не ограничивается вершинами или случайными точками. Вычисления используют float64 и численный запас; это не доказательство в точной арифметике.

Если допуск не подтверждён, достигнут предел работы проверяющего алгоритма, изменилось число оболочек или появились дефекты топологии, **упрощение отменяется**, а исправленная сетка сохраняется без него. Процент уменьшения не задан заранее: он зависит от формы и допуска. В журнале выводится число треугольников до и после; в JSON — блок `simplification` с результатом проверки.

## Что считается результатом

Сохраняется один STL с замкнутыми поверхностями без обнаруженных самопересечений. Пересекающиеся/вложенные оболочки по возможности объединяются. Обработка как сплошных тел **может удалить внутренние полости**.

Если детали физически разнесены, файл может содержать несколько замкнутых оболочек: приложение **сохранит их и явно сообщит число**, а не откажет в сохранении. Перемычки не добавляются, отдельные детали не удаляются специально. Один STL не всегда означает одно связное тело. Элементы меньше выбранного разрешения могут исчезнуть при восстановлении; проверяйте форму.

Программа не может гарантировать корректную реконструкцию любой произвольно повреждённой геометрии. Восстановление по дырявым поверхностям/смешанным нормалям неоднозначно. Если результат не прошёл финальную проверку, повреждённый STL не выдаётся как успешный результат. Проверьте форму в Rhino перед изготовлением.

## Значение качества

В объёмном восстановлении качество задаёт **шаг вокселя в миллиметрах**. В поверхностном ремонте исправная геометрия сохраняется; она не упрощается принудительно ради более грубого выбранного качества.

Это **не сертифицированное максимальное отклонение всего ремонта от исходника**. `tolerance_certified` в отчёте всегда `false`. Заплатки, удалённые внутренние оболочки и восстановление могут отклоняться от исходника сильнее шага. Очистка вырожденных граней использует отдельный малый допуск 1% шага. Отдельная проверка `simplification.verification` относится только к дополнительному упрощению относительно исправленной сетки. STL/нативные координаты имеют конечную численную точность.

## Скорость и память

C++-ядро MeshLib использует многопоточность на поддерживаемых этапах. Для разреженного восстановления автоматически пробуется CUDA winding number; построение OpenVDB/топологические операции остаются на CPU. Если CUDA недоступна или завершилась ошибкой, применяется CPU с тем же качеством.

Упрощение выполняется на CPU, для сеток от 50 тысяч граней — с разбиением на части для параллельной обработки. Во время параллельного схлопывания показываются начало и конец этапа: Python-callback прогресса в закреплённой версии SDK вызывает взаимную блокировку потоков и здесь отключён. Кнопка остановки продолжает работать. Поиск проекций при проверке поверхности также выполняется нативным ядром. Дополнительная проверка отклонения требует времени и памяти; на сложных сетках и малом допуске она может занять больше времени, чем сам ремонт.

Размер плотного объёма больше не служит причиной отказа, но разреженные данные также могут быть огромными. **0,001 мм на крупной модели может потребовать много времени и RAM.** Программа не снижает качество скрыто. Пользователь может остановить расчёт и выбрать более грубое качество. Реальная скорость зависит не только от числа треугольников, но и от площади, разрешения, дыр и структуры пересечений. Обещания «любой mesh за 2–3 минуты» нет.

В репозитории есть тест с 1150 открытыми оболочками и benchmark объединения 338 тысяч треугольников. Эти искусственные модели не заменяют испытания реальных `444.stl` и `bl2rh.obj`; сами эти файлы для разработки пока не предоставлены. Работа GPU на пользовательской RTX 3090 также не проверена.

## Отмена и сохранение

Тяжёлая работа выполняется в отдельном процессе, поэтому интерфейс и остановка не зависят от блокирующего вызова C++. После остановки могут остаться временные `.meshrepair-*` файлы — их можно удалить. В короткий момент публикации может остаться полный STL без JSON; это не завершённый отчёт приложения.

Результат публикуется через hard link без перезаписи: выходная папка должна поддерживать hard links (локальный NTFS на Windows). FAT32/exFAT не подходят. Исходник не меняется.

## Для разработчика

```text
python -m meshrepair.worker input.stl --quality 0.02
python -m meshrepair.worker input.stl --quality 0.1 --output repaired.stl
python -m meshrepair.worker input.stl --quality 0.02 --collapse-coplanar --coplanar-angle 1 --simplify-curved
python -m pytest -q
python tests/benchmark_synthetic.py
```

`--debug` включает стек ошибки. Остальные прежние параметры режимов/лимитов удалены.
