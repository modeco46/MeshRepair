# MeshRepair 1.0.1

- Исправлен полный откат упрощения на сложных моделях: каждый проход проверяется отдельно относительно неизменной поверхности после ремонта. Если следующий проход превышает допуск или создаёт пересечение, сохраняется предыдущий проверенный результат.
- Тонкие отдельные оболочки проверяются независимо; неудачный проход такой оболочки откатывается без отмены упрощения основного тела. Итоговая сетка по-прежнему проверяется целиком.
- Убран нижний предел масштаба ошибки 0,15. Поиск может перейти к более щадящему упрощению. Разделение на оболочки выполняется один раз на весь подбор допуска.
- Единичные пересечения обычной воксельной поверхности исправляются локально. Принимается только замкнутый результат без пересечений, с прежним числом оболочек и доказанным отклонением не более четверти шага. Глобальная предварительная обработка касаний MeshLib отключена в этом этапе, чтобы не удалять посторонние мелкие оболочки. Полный Sharpening в этот этап не передаётся.
- Для уже замкнутого входа большой CPU-расчёт Marching Cubes пропускает winding далеко от поверхности. При появлении отверстий выполняется повтор с полным полем. Открытые входы и CUDA сохраняют прежний расчёт.
- Убрана ошибочная рекомендация выключить острые рёбра при отказе обычного восстановления. JSON хранит проверки промежуточных проходов, откаты оболочек и результаты локального ремонта.

Исправления проверяются на предоставленном OBJ из 894 562 треугольников; файл модели не включён в репозиторий. Результаты и границы проверки — в [отчёте 1.0.1](docs/complex-mesh-1.0.1.md).

# MeshRepair 1.0.0

- Исправлен отказ всего упрощения с `kept_shell_count_changed`: каждая оболочка получает отдельный предел удаления граней на каждом проходе. Физически маленькие тела с сотнями/тысячами граней больше не исчезают целиком. Существующая защита исходных компонентов <50 граней сохранена.
- Схлопывание плоскостей и проходы с закреплёнными углами/границами выполняются без разбиения, поскольку параллельный путь MeshLib 3.1.4.297 подменяет список закреплённых вершин. Для остальных оболочек сохранены нативная многопоточность и обработка стыков; число участков ограничено восемью.
- Большие воксельные объёмы (>64 млн ячеек bbox) восстанавливаются через Marching Cubes по слоям/частям, без уплотнения всего bbox в OpenVDB. Шаг и допуск не увеличиваются. CPU использует `memoryEfficient`, CUDA — интерфейс вычисления по частям; при ошибке CUDA остаётся CPU fallback.
- В журнал добавлены объём воксельной сетки, выбранный способ восстановления, фазы обычного OpenVDB-пути, количество треугольников и время каждого прохода, причины отклонения каждой попытки. JSON содержит параметры отдельных оболочек и проходов.
- Добавлены регрессии на 786 432 плоских гранях, 806 400 гранях с девятью оболочками, сохранение открытого контура и реальный нативный путь восстановления по слоям. Проверки топологии, самопересечений, числа оболочек, допуска и итогового STL сохранены.

Фактические OBJ/STL двух проблемных моделей и физическая RTX 3090 в этой среде недоступны. Результаты синтетических проверок и границы проверки описаны в `docs/large-mesh-1.0.md`.
