# MeshRepair 1.0.0

Версия 1.0.0 исправляет отказы на крупных моделях (от ~300 тыс. треугольников): раньше результат получался
без упрощения (3 млн треугольников, 150 МБ STL), с ложным предупреждением об отклонении или вообще не завершался.

## Что было причиной
- **Упрощение отклонялось целиком.** После воксельного ремонта в модели оставались внутренние полости и
  пластины нулевой толщины (в журнале: «Удалено мелких оболочек: 50», «9 замкнутых оболочек»). Они были
  больше порога «мелкой оболочки» (50 граней), упрощение меняло число оболочек и создавало пересечения, и все
  шесть попыток (по ~18 с) отбрасывались: `kept_shell_count_changed`. Разбиение на части (`subdivideParts`)
  к этому отношения не имеет: при 1 и при 8 частях результат одинаков (26 580 и 26 616 треугольников).
- **Лишние воксели.** Когда замкнутые оболочки только пересекают друг друга (проушина, зацепы, камни), модель
  вокселизировалась целиком, хотя точное булево объединение быстрее и не оставляет полостей
  (1,9 с против 15 с на тестовой модели).
- **Ложное «Отклонение 0,556 мм».** Вершины внутренних поверхностей исходника, которые объединение убирает
  намеренно, считались отклонением формы.
- **Время воксельного расчёта оценивалось по площади**, а оно растёт с числом ячеек габаритного бокса
  (кольцо с пустым центром считается заметно дольше, чем показывала оценка).

## Что изменено
- Булево объединение для случая «пересечения только между оболочками» (без вокселей, лимит времени 240 с).
- После воксельного ремонта удаляются внутренние полости и оболочки нулевой толщины.
- Если общий проход упрощения меняет оболочки, после первой же неудачи упрощение идёт по каждой оболочке
  отдельно (число оболочек сохраняется), без шести повторов.
- Отклонение не учитывает вершины исходника, лежащие внутри результата (точный тест по псевдонормалям,
  корректный на вогнутых рёбрах). Они выводятся отдельно: `interior_vertices`, `max_deviation_all_mm`.
- Воксельный расчёт: размеры сетки в журнале, оценка времени по пробе на сетке с шагом ×4 (в 64 раза
  дешевле), предупреждение с подсказкой допуска, ранний отказ при сетке больше 6 млрд ячеек.
- Режим «только плоские» не делится на части (швы разбиения оставляли лишние треугольники: 252 вместо 12
  на кубе в 6,3 млн треугольников).

- Подготовка оболочек выполняется один раз на подбор допуска. Для единственной оставшейся оболочки сохраняется допустимый промежуточный QEM-проход; поиск может снижать масштаб ошибки ниже 0,15.
- Большие воксельные объёмы рассчитываются по слоям/частям. Единичные пересечения обычной воксельной поверхности исправляются локально только с проверенной границей смещения ≤¼ шага и сохранением оболочек.
- Исправлены обработка позднего завершения булевой операции и очистка строки об удалённых полостях при откате экспорта. Тесты Sharpening явно выбирают воксельный путь, не отключая новый булев маршрут в приложении.

## Версия 0.9.1

- Общее упрощение: до трёх QEM-проходов и подбор масштаба допуска. Все проверки относительно сетки до упрощения. На test.stl: 209 466 → 26 826 треугольников; строгое доказательство ≤0,02 мм; упрощение 11,34 с на одном CPU.
- Новый блок отчёта показывает треугольники на больших плоскостях, остатки исходника p50/p90 и объяснение влияния шума. Подсказка о допуске — явно обозначенная эвристика; сглаживание шума не добавлено.
- Windows запускается без терминала: один windowed EXE, pythonw для исходников, прогресс через файл каждые 200 мс. Журнал с ротацией и faulthandler, сообщение о критической ошибке с путём к журналу. PE-подсистема и отсутствие консоли проверяются в Windows CI.

- Невалидный полный Sharpening автоматически заменяется обычным offsetMesh при оценке повторного расчёта до 120 с. Для более дорогого расчёта есть кнопка «Повторить без Sharpening» с прежними настройками. Причина и время видны в отчёте. CutAndFill к полному Sharpening не применяется.
- Заплатки с самопересечениями принимаются условно и исправляются общим локальным CutAndFill в пределах порога. При неудаче они полностью откатываются, включая изменения старых вершин, и выполняется воксельный путь.
- На регрессионной сфере R=5, UV 200×200: 38 → 0 дыр, четыре заплатки исправлены, 23 → 0 пересечений, одна замкнутая оболочка, 76 904 треугольника, отклонение поверхности 0,03466 мм, 3,50 с на CPU. Воксели не потребовались.
- CUDA winding повторно используется между проходами; нативная многопоточность и проверки в памяти сохранены. Измерения CPU и проверки CUDA-интерфейса не заменяют измерения на физической GPU.
- Все PR, включая внутренние, запускают Linux/Windows тесты и сборку Windows EXE до merge. Автономный тест собранного приложения защищён от импортов исходного пакета. Публикация использует только проверенный коммит main.
- Добавлены сквозные регрессионные тесты engine.run и проверка кнопки повтора. Русский интерфейс сохранён.
