# MeshRepair 1.0.0

- Исправлен отказ всего упрощения с `kept_shell_count_changed`: каждая оболочка получает отдельный предел удаления граней на каждом проходе. Физически маленькие тела с сотнями/тысячами граней больше не исчезают целиком. Существующая защита исходных компонентов <50 граней сохранена.
- Схлопывание плоскостей и проходы с закреплёнными углами/границами выполняются без разбиения, поскольку параллельный путь MeshLib 3.1.4.297 подменяет список закреплённых вершин. Для остальных оболочек сохранены нативная многопоточность и обработка стыков; число участков ограничено восемью.
- Большие воксельные объёмы (>64 млн ячеек bbox) восстанавливаются через Marching Cubes по слоям/частям, без уплотнения всего bbox в OpenVDB. Шаг и допуск не увеличиваются. CPU использует `memoryEfficient`, CUDA — интерфейс вычисления по частям; при ошибке CUDA остаётся CPU fallback.
- В журнал добавлены объём воксельной сетки, выбранный способ восстановления, фазы обычного OpenVDB-пути, количество треугольников и время каждого прохода, причины отклонения каждой попытки. JSON содержит параметры отдельных оболочек и проходов.
- Добавлены регрессии на 786 432 плоских гранях, 806 400 гранях с девятью оболочками, сохранение открытого контура и реальный нативный путь восстановления по слоям. Проверки топологии, самопересечений, числа оболочек, допуска и итогового STL сохранены.

Фактические OBJ/STL двух проблемных моделей и физическая RTX 3090 в этой среде недоступны. Результаты синтетических проверок и границы проверки описаны в `docs/large-mesh-1.0.md`.
